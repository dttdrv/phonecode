# Misul Android Runtime Input

PhoneCode consumes a separately built Misul Android library. The Zig source remains owned by `/Users/dttdrv/Projects/Misul-Terminal/MisulAgent`; this directory contains only the immutable consumer contract and staging checks.

Build the pinned input locally with:

```sh
ANDROID_NDK_HOME=/Users/dttdrv/Library/Android/sdk/ndk/28.2.13676358 \
ZIG=/Users/dttdrv/.codex/toolchains/zig-0.16.0/zig \
/Users/dttdrv/Projects/Misul-Terminal/MisulAgent/scripts/build-android-arm64.sh /absolute/output/path
```

Then run the staging contract with `MISUL_ANDROID_RUNTIME_DIR=/absolute/output/path`. The source tree and downloads are not vendored into PhoneCode. The locked `libmisul.so` and its provenance are committed as distributable app inputs so local and CI sideload builds cannot silently omit the runtime. Replace them only with staging output that matches `native-misul/sources.lock`.

Before building the current PhoneCode runtime, apply `native-misul/patches/provider-failure-rpc.patch`, `native-misul/patches/android-https-transport.patch`, `native-misul/patches/openrouter-final-usage.patch`, `native-misul/patches/openai-stream-tail-tolerance.patch`, and `native-misul/patches/host-tools-parallel.patch` to the Misul source, in that order. Apply the zero-context transport patch with `git apply --unidiff-zero`. The first patch preserves Misul's structured, redacted provider failure in the Android RPC settlement. The second uses Android's dual-stack resolver, races the returned addresses, and eagerly loads Android's system CA bundle before native HTTPS, avoiding Zig's Linux resolver path inside the app process without narrowing custom providers to IPv4. The third accepts OpenRouter's final usage event when it repeats a completed choice with an empty delta; any new content after the finish reason is still rejected. The fourth generalizes that for every OpenAI-compatible dialect: after the finish reason it accepts inert chunks (at most one choice at index 0 whose delta has no text, reasoning, reasoning details, or tool calls, an assistant or null role, and the same or null finish reason), usage-only chunks without `choices`, metadata-only chunks, and repeated or refined usage (the latest report wins). It derives `total_tokens` from prompt and completion counts instead of failing on a mismatch, and reports `finish_reason: "error"` as a provider failure. New output, a changed finish reason, extra choices, or non-numeric usage after the finish reason are still malformed. The fifth patch lets the Android host register its own tools (`host_tools` in the open configuration, executed through `host_tool_request` records and `tool_result` host responses), disable tools, and force approval for named tools; it runs the read-only tool calls of one response concurrently, while mutating or sequential tools run alone in call order, approvals stay sequential, and results stay in call order; it accepts tool calls with empty arguments or a `stop` finish reason, ignores unknown argument fields, maps absolute workspace and `/workspace` paths onto the workspace root, explains common tool errors to the model, and raises the advertised tool limit from 16 to 128.

The 0.6 beta runs prompts, native file tools, approvals, cancellation, and durable session import through this in-process runtime. PhoneCode has no packaged Kotlin agent fallback. The source lock must be updated only from a freshly audited Misul Android build.
