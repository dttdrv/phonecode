# PhoneCode 0.5.0 Release Design

## Product direction

PhoneCode 0.5.0 keeps the existing monochrome, native Android identity. The release improves hierarchy, touch feedback, motion, onboarding clarity, and Play-release integrity without introducing a new visual language or decorative artwork.

The user's explicit direction is the approval boundary:

- make the composer visibly rounder;
- replace the attachment paperclip with a plus;
- improve buttons and their states;
- improve onboarding and model setup;
- preserve and improve professional motion;
- validate on the Android emulator, update screenshots, merge to `main`, and publish 0.5.0.

## Composer

The resting composer is a true capsule. Its fixed corner radius is 30dp, matching half of the 60dp resting outer height. Multiline expansion retains the same 30dp radius so corners remain generous without becoming a distorted percent-based stadium.

The leading attachment action uses the Material `Add` icon and the accessible label `Add attachment`. Its behavior remains the safe system document/photo picker. The send/stop control remains a 48dp circular action and crossfades between states without rotating or bouncing.

## Buttons

Full-width buttons use an 18dp shape, a 56dp primary onboarding height, explicit enabled/disabled colors, and the existing immediate 0.97 press scale with critically damped release. Icon buttons retain 48dp targets. Color/state transitions are short and do not animate layout.

Primary actions are filled. Secondary and skip actions are visually quieter. Destructive actions remain semantically distinct. Disabled buttons stay legible but cannot compete with enabled actions.

## Onboarding

The strong welcome screen stays recognizable. The second step becomes a concise setup checklist:

- Model: required for agent work.
- Project folder: recommended for real project work.
- GitHub: optional for repository sync.

The page header exposes progress without the oversized `2 of 2` treatment. Completion uses a check icon and state copy. The main CTA is stable at the bottom, while the skip action remains available and honestly leads to the model-required empty state.

Model setup presents recommended providers first (OpenAI, Anthropic, and Google Gemini), then reveals the remaining providers through an explicit `More providers` control. ChatGPT sign-in remains visible only when supported by the build. Credentials continue to use Android secure storage.

## Motion and accessibility

Movement is limited to state changes that benefit from spatial continuity:

- onboarding pages slide/fade with the existing iOS-style ease-out curve;
- provider expansion uses an interruptible content-size spring;
- send/stop and completion indicators use scale from 0.92 plus opacity;
- button press feedback is immediate and releases through a critically damped spring.

No animation blocks interaction. All controls keep at least 48dp targets. Motion semantics and content descriptions are covered by Compose tests. Reduced-motion behavior is validated where platform duration scale is available; essential state feedback remains visible without relying on movement alone.

## Approval and whole-app consistency

Approval is a decision workflow, not a generic alert. The surface identifies the tool requesting access, summarizes the exact action in a scroll-safe region, distinguishes the safe denial path from the intentional approval action, and prevents duplicate submission. It remains calm and monochrome while using text, hierarchy, and semantics to communicate risk rather than decorative warning color.

Every reachable screen uses the same visual grammar: compact section labels, readable titles, grouped rows, 48dp controls, persistent field labels, explicit loading/error/empty states, and restrained motion for true hierarchy changes. Settings, MCP and skill details, model credentials, the drawer, onboarding, chat, and approval states are reviewed at the same viewport and density. Refinement is accepted only after screenshot comparison catches no clipping, accidental density changes, uneven spacing, unclear action hierarchy, or unsupported placeholder content.

## Release boundary

The version becomes 0.5.0 with a monotonically increased version code. Debug-only prototype rootfs/proot assets remain excluded from release. The release gate must continue to fail closed for missing signing, immutable guest artifacts, legal evidence, or reviewer evidence. No credential, attestation, source archive, or device result may be fabricated.

Local work is complete only after unit/UI/native/backend tests, lint, a fresh release bundle, artifact inspection, StoreReady, Play policy checks, emulator screenshots, and remote Git verification. External Play Console submissions remain external actions, even when the local release bundle is ready.
