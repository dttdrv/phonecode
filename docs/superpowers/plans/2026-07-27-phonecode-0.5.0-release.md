# PhoneCode 0.5.0 Release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver a polished, tested PhoneCode 0.5.0 Android release candidate with improved composer, buttons, onboarding, screenshots, motion, and fail-closed Play evidence.

**Architecture:** Extend the existing Compose component and motion tokens rather than adding a parallel design system. Keep UI work isolated from guest-runtime and legal-evidence work, integrate only after focused tests pass, and finish with a clean release-artifact audit.

**Tech Stack:** Kotlin, Jetpack Compose Material 3, Robolectric Compose UI tests, Roborazzi, Gradle/AGP, native QEMU guest runtime, Cloudflare Worker tests, StoreReady.

## Global Constraints

- Keep `dev.phonecode` as the application ID.
- Set release version to `0.5.0` and increase `versionCode` above 40.
- Do not add a UI dependency or custom icon asset for standard Material actions.
- Keep every interactive target at least 48dp.
- Keep UI transitions below 300ms and use shared motion tokens.
- Do not fabricate signing credentials, OAuth ownership, source archives, legal evidence, Play Console declarations, or physical-device evidence.
- Keep release verification fail-closed when required evidence is absent.
